A retenir pour une prochaine tentative:
 
Dans DB Browser for SQLite, tu n'as pas besoin d'ouvrir deux instances : la fonctionnalité native Attacher une base de données (Attach Database) permet d'interroger et de croiser deux fichiers .sqlite simultanément dans la même session.

Ouvre ta base principale (db-public.sqlite ou ton backup) dans DB Browser.

Va dans Fichier > Attacher une base de données (ou Ctrl + Shift + A) et sélectionne le second fichier .sqlite.

Vérification : Dans l'onglet Structure de la base de données, les tables de la seconde base apparaissent désormais sous un alias (par défaut le nom du fichier, ex: backup ou pub).

Dans l'onglet Exécuter le SQL, tu peux alors requêter les deux bases en préfixant les tables par main. et <alias>. :

SQL
-- Exemple : lister les sorts présents dans la base attachée mais absents de la base principale
SELECT SpellID, Name, Type FROM pub.Spell
WHERE SpellID NOT IN (SELECT SpellID FROM main.Spell);
Pour détacher la seconde base une fois tes requêtes terminées : Fichier > Détacher la base de données. Bonne soirée !

Les 2900 lignes de différence viennent du fait que db-public inclut tous les sorts de procs d'objets, les sorts des mobs/boss de raids et les extensions post-ToA. Pour ne pas te noyer dans ces 2900 entrées, il faut croiser Spell avec LineXSpell pour isoler uniquement les sorts de joueurs.1. Isoler uniquement les vrais sorts de classes manquants dans ton backupFiltre sur les lignes de spécialisation actives de ta base actuelle :SQLSELECT p.LineName, p.Level, s.SpellID, s.Name, s.Type, s.Value, s.Power
FROM public.LineXSpell p
JOIN public.Spell s ON p.SpellID = s.SpellID
WHERE p.LineName IN (SELECT DISTINCT LineName FROM main.LineXSpell)
  AND s.SpellID NOT IN (SELECT SpellID FROM main.Spell)
ORDER BY p.LineName, p.Level;
Vérification : Cette requête réduit les 2900 lignes aux seuls sorts ajoutés sur les lignes de spé existantes (comme les chants/sorts post-1.65 du Skald, Ménestrel, Barde, etc.) et élimine tout le bruit des sorts de PNJ/items.2.
