### Ajouter une ligne de compétence à une classe (exemple : bouclier pour le Warden, classe 46)

- C'est dans le **SQL**, pas dans `SpellLine` (`Skill.cs:186`, qui est une ligne de **sorts**). Les lignes d'une classe viennent de la table `ClassXSpecialization` (`ClassID`, `SpecKeyName`, `LevelAcquired`), lue au démarrage par `SkillBase.LoadClassSpecializations()`. `ClassWarden.cs` ne liste aucune spécialisation.
- « Bouclier » = deux choses : la capacité `Shield` (niveaux 1/2/3 = petit/moyen/grand, table `SpecXAbility` ; sans elle, blocage = 0) et la ligne entraînable `Shields` (score de bouclier + styles).
- Les **styles** sont des lignes de la table `Style` (`SpecKeyName`, `ClassId`, `SpecLevelRequirement`, conditions d'ouverture, résultat d'attaque requis, `WeaponTypeRequirement` = Shield) et `StyleXSpell` pour les effets. Clé : `Style.ID` + `ClassId`.
- Décisif : `Specialization.GetStylesForLiving` cherche d'abord les styles de la classe (`ClassId` = 46), **sinon retombe sur `ClassId = 0`**. Si les styles de bouclier existants sont à 0, donner la ligne suffit ; s'ils sont par classe, copier les lignes `Style` (nouveaux `StyleID`, même `ID`) et `StyleXSpell` vers 46. Les requêtes de lecture pour trancher sont dans la section 7 de la note.
- Une seule clé `Specs.Shields = "Shields"` dans le code (les armes ont une clé par royaume) : la ligne est partagée ; la base pourrait en contenir d'autres (`SELECT KeyName FROM Specialization WHERE KeyName LIKE '%hield%'`).
- Modèle dans le dépôt : `tools/claude-version/seed_sluaghbinder.py` (classe 63). Bots : `WardenBotSpec` ne connaît pas `Shields`.
- Non validé : limites du client 1.65 pour des styles ajoutés à une classe qui n'en avait pas.
